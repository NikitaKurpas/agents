# Xcode projects (`project.xcproj`)

Xcode 27.2 stores a project's build graph inside the `.xcodeproj` bundle as either legacy `project.pbxproj` or JSON5 `project.xcproj`. Schemes, workspaces, `Package.resolved`, and `xcuserdata` stay as they were.

## Policy

- Every Xcode project uses the JSON format. `xcodeproj init` creates one.
- A project still on `project.pbxproj` gets converted first, as its own change on a clean working tree, before the requested edit.
- For projects generated by Tuist, XcodeGen, or similar, edit the manifest and let the generator own the format.
- Make every edit through `xcrun xcodeproj`: it generates IDs, checks dependency cycles, and keeps the file canonical. Hand-edit `project.xcproj` only where the CLI has no command.

## Tools

Each needs Xcode 27.2+ and runs through `xcrun`, since none is on `PATH` and a bare `xcodeproj` may be the CocoaPods gem.

| Tool | Does |
| --- | --- |
| `xcodebuild -project App.xcodeproj -convert-project xcproj` | Converts to JSON in place, replacing the old file (`pbxproj` converts back). |
| `xcrun xcodeproj <cmd>` | Edits targets, phases, groups, build settings, xcconfig links, and packages, in either format. Schemes, workspaces, and xcconfig contents are out of its reach. |
| `xcrun xcprojformatter` | Validates `project.xcproj` and prints it canonically. |

## Discover

`xcodeproj` help is the reference: it explains each edge case, and errors list the valid names. Read the help for a command before its first use.

```bash
xcrun xcodeproj help [<cmd> [<subcmd>]]
xcrun xcodeproj target list
xcrun xcodeproj target info --target App   # product type, deps, numbered phases
xcrun xcodeproj group ls
xcrun xcodeproj pkg list
xcrun xcodeproj setting list [--target App]
```

With several `.xcodeproj` in the directory, pass `--project <path>` or set `XCODEPROJ_PROJECT`.

Addressing: groups are navigator paths like `/App/Sources`, and phases are the indexes `target info` prints. `setting get/list` show raw values; `xcodebuild -showBuildSettings` shows resolved ones.

For creating a project, adding targets or tests, build settings, xcconfig files, packages, and merge conflicts, read [references/recipes.md](references/recipes.md).
